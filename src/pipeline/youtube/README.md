# YouTube Pipeline Module

Streamlined YouTube video metadata management for conference videos.

## Overview

This module provides a simplified, single-channel focused approach to updating YouTube video metadata. It separates the preparation phase (for review) from the sending phase (API interaction), allowing for quality control and batch processing.

## Key Features

- **Single-channel focus**: Simplified from multi-channel complexity
- **Review workflow**: Prepare metadata for review before sending
- **Status tracking**: File movement by status (pending → completed/failed)
- **Quota management**: Respects YouTube API quotas (200 videos/day)
- **Batch and single video support**: Flexible processing options
- **Error recovery**: Failed updates can be reset and retried

## Prerequisites

### Required Files

Before using this module, ensure you have:

1. **Pretalx Records**: `.work/{event}/pretalx_records/{id}.json`
   - Session data from conference system
   - Generated by: `fetch_pretalx.py`

2. **YouTube ID Mapping**: `.work/{event}/pretalx_youtube_map/mapping.json`
   ```json
   {
     "mappings": {
       "LRUKZQ": "dQw4w9WgXcQ",
       "3CYZUH": "oHg5SJYRHA0"
     }
   }
   ```
   - Maps Pretalx session IDs to YouTube video IDs
   - Created after manual video upload

3. **AI Summaries** (Optional): `.work/{event}/summaries/{id}.json`
   - Enhanced descriptions from AI processing
   - Generated by: `text_generation.generate_summaries`

4. **Description Template**: `src/manager/templates/youtube_2025.txt`
   - Jinja2 template for formatting descriptions

### Configuration

In `config_local.yaml`:

```yaml
youtube:
  client_secrets_file: "client_secrets.json"
  privacy_status: "unlisted"  # or "public", "private"

pretalx:
  event_slug: "pyconde-pydata-2025"

event:
  name: "PyConDE & PyData Berlin 2025"
```

### OAuth2 Setup

1. Download OAuth2 client secrets from Google Cloud Console
2. Save as `client_secrets.json` in project root
3. First run will open browser for authentication
4. Token saved to `.secrets/youtube_token.json`

## Directory Structure

```
.work/{event}/
├── pretalx_records/        # Input: Session data
├── summaries/              # Input: AI-generated summaries (optional)
├── pretalx_youtube_map/    # YouTube ID mapping
│   └── mapping.json        # Pretalx ID → YouTube ID mapping
└── youtube/
    ├── pending/            # Metadata ready to send
    ├── completed/          # Successfully updated videos
    ├── failed/             # Failed updates (can retry)
    └── status.json         # Update tracking
```

## Usage

### Step 1: Prepare Metadata (Review Phase)

Generate YouTube metadata files for review:

```bash
# Prepare all mapped videos
python -m src.pipeline.youtube.prepare_metadata --all

# Prepare specific videos
python -m src.pipeline.youtube.prepare_metadata LRUKZQ 3CYZUH 7FLW7F

# Force regeneration (if template changed)
python -m src.pipeline.youtube.prepare_metadata --all --force
```

This creates JSON files in `youtube/pending/` with:
- Video title
- Rendered description (from template + AI summary)
- Tags (base tags + AI-generated tags)
- Privacy settings

**Review the generated files before proceeding!**

### Step 2: Send Updates (Execution Phase)

Send prepared metadata to YouTube API:

```bash
# Dry run (preview without sending)
python -m src.pipeline.youtube.send_updates --dry-run --limit 5

# Send all pending updates
python -m src.pipeline.youtube.send_updates

# Send specific videos
python -m src.pipeline.youtube.send_updates LRUKZQ 3CYZUH

# Limit number (for testing or quota management)
python -m src.pipeline.youtube.send_updates --limit 50

# Check current status
python -m src.pipeline.youtube.send_updates --status
```

### Handling Failures

If updates fail, files move to `failed/` directory:

```bash
# Reset failed videos for retry
python -m src.pipeline.youtube.send_updates --reset-failed

# Then send again
python -m src.pipeline.youtube.send_updates
```

## File Movement Flow

```
1. prepare_metadata creates → pending/{id}.json
2. send_updates processes:
   - Success → completed/{id}.json + {id}_TIMESTAMP_response.json
   - Failure → failed/{id}.json + {id}_TIMESTAMP_error.json
3. Reset moves failed/ → pending/ for retry
```

## Status Tracking

The `status.json` file tracks all updates:

```json
{
  "total_videos": 150,
  "pending": 10,
  "processing": 0,
  "completed": 138,
  "failed": 2,
  "last_run": "2025-01-06T10:30:00Z",
  "videos": {
    "LRUKZQ": {
      "youtube_id": "dQw4w9WgXcQ",
      "status": "completed",
      "attempts": 1,
      "last_attempt": "2025-01-06T10:30:00Z"
    }
  }
}
```

## Quota Management

- **Cost**: 50 quota units per update
- **Daily limit**: 10,000 units (~200 videos)
- **Reset time**: Midnight Pacific Time (PT)
- Script automatically stops when quota exceeded
- Resume next day or request quota increase

## Complete Workflow Example

```bash
# 1. Ensure prerequisites exist
ls .work/pyconde-pydata-2025/pretalx_records/
ls .work/pyconde-pydata-2025/summaries/
cat .work/pyconde-pydata-2025/pretalx_youtube_map/mapping.json

# 2. Prepare metadata for review
python -m src.pipeline.youtube.prepare_metadata --all

# 3. Review generated files
ls .work/pyconde-pydata-2025/youtube/pending/
# Check descriptions, tags, etc.

# 4. Test with dry run
python -m src.pipeline.youtube.send_updates --dry-run --limit 5

# 5. Send first batch
python -m src.pipeline.youtube.send_updates --limit 10

# 6. Check results
python -m src.pipeline.youtube.send_updates --status

# 7. Continue with remaining
python -m src.pipeline.youtube.send_updates
```

## Re-processing Videos

To update videos with new metadata (e.g., improved summaries):

```bash
# 1. Force regenerate metadata
python -m src.pipeline.youtube.prepare_metadata --all --force

# 2. Send updates (YouTube allows re-updating)
python -m src.pipeline.youtube.send_updates
```

## Module Components

### `prepare_metadata.py`
- Combines pretalx records, AI summaries, and mappings
- Renders descriptions using Jinja2 templates
- Generates API-ready metadata files
- Supports batch and single video processing

### `send_updates.py`
- Processes files from `pending/` directory
- Handles YouTube API authentication
- Manages quota limits (stops at 10,000 units)
- Moves files by status for tracking
- Supports dry-run mode for testing

### `auth.py`
- Single-channel OAuth2 authentication
- Token management and refresh
- Lazy service initialization

### `models.py`
- Pydantic models for type safety
- `YouTubeMetadata`: API request structure
- `UpdateStatus`: Tracking information
- `YouTubeMapping`: ID mappings

### `status.py`
- Status tracking and reporting
- Manages `status.json` file
- Query and reset capabilities

## Troubleshooting

### No pending updates found
- Run `prepare_metadata` first to generate files
- Check that YouTube ID mapping exists

### 403 Forbidden
- Check OAuth authentication
- Verify channel permissions
- May indicate quota exceeded

### Quota exceeded
- Wait until midnight PT for reset
- Or request higher quota from Google

### Missing AI summaries
- Summaries are optional but recommended
- Run `text_generation.generate_summaries` first
- Will fall back to basic abstract if unavailable

## API Response Files

Successful updates create response files in `completed/`:
- `{id}.json`: Original metadata sent
- `{id}_TIMESTAMP_response.json`: API response

Failed updates create error files in `failed/`:
- `{id}.json`: Original metadata (for retry)
- `{id}_TIMESTAMP_error.json`: Error details
